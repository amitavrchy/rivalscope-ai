১০. নতুন security ও collaboration সুবিধা

Settings → Your profile → Save profile দিয়ে display name বদলান। Active sessions-এ নিজের ও অন্য browser-এর session দেখুন; Revoke দিয়ে বন্ধ করুন। নিজের session বন্ধ করলে আবার sign in করতে হবে।

Settings → Two-step verification-এ current password দিয়ে Set up authenticator চাপুন। Authenticator app-এ setup key যোগ করে time-based ছয় সংখ্যার code নিন। Verify & enable MFA চাপুন। দেখানো recovery codes নিরাপদে রাখুন—প্রতিটি একবার ব্যবহার করা যায় এবং পরে একই তালিকা আর দেখা যায় না। Login-এ password-এর পরে authenticator অথবা recovery code লাগবে। Replace recovery codes দিলে পুরোনোগুলো বাতিল হয়। MFA চালু/বন্ধ করলে অন্য session-গুলো বন্ধ হয়।

Google OAuth configured থাকলে login-এর Google button ব্যবহার করতে পারবেন। আগে password দিয়ে account খুলে থাকলে Settings → Google sign-in → Connect Google থেকে একই email-এর Google account যুক্ত করুন। Credential setup না থাকলে পরিষ্কার setup message দেখাবে।

Research → Project collaboration-এ team note, ব্যক্তিগত bookmark ও participants পাবেন। Team note দল দেখতে পারে; personal bookmark শুধু নিজের। Participant assignment workspace role বদলায় না এবং project-কে private করে না।

Comparisons-এ project ও competitor নির্বাচন করুন। Feature-এর quotation ও pricing source খুলে দেখুন। প্রকাশিত তথ্য না থাকলে gap দেখাবে; অনুমান করে দাম বসানো হয় না। Chart-এ compatible monthly prices ও documented feature count দেখা যায়—এটি market share বা product quality score নয়। Edit permission থাকলে selection-এর নাম দিয়ে comparison save করতে পারবেন।

Settings → Email notification preferences-এ instant, daily বা weekly বেছে save করুন। Alerts → Mark read শুধু নিজের read state বদলায়। Workspace owner/admin Integrations থেকে Slack/Discord incoming webhook যুক্ত করতে পারেন।

Alerts → Watch phrase rules-এ monitor, rule name, exact phrase, appeared/disappeared condition এবং নিজের priority বেছে Create alert rule চাপুন। Monitoring-এর পর পরবর্তী snapshots-এ phrase নতুন করে আসা বা চলে গেলে alert হবে। এটি literal text rule; business change নিশ্চিত করার জন্য snapshot দেখুন। Rule pause/enable করা যায়। Delete করলে তার matched history-ও মুছে যায়—confirmation পড়ে সিদ্ধান্ত নিন।

Owner ও billing manager Billing & usage → Consumption by activity-এ research/copilot/monitoring-এর actual credit consumption এবং গত ৩০ দিনের daily totals দেখতে পারেন। Grant ও temporary reservation consumption হিসেবে গণনা হয় না।

Settings → Data exports → Export account JSON নিজের account data দেয়। Deletion controls-এ password ও MFA দিয়ে নির্দিষ্ট confirmation phrase লিখতে হয়। Account মুছতে আগে নিজের সব workspace-এর ownership transfer বা workspace delete করতে হবে। Workspace deletion-এর অনুমতি শুধু owner-এর। প্রয়োজনীয় pseudonymous audit ও accounting records রাখা হয়।

৫. Billing portal থেকে Stripe account-এর portal configuration অনুযায়ী subscription/payment management হবে।

Checkout থেকে ফিরে এলেই account paid হয়েছে ধরে নেবেন না; server-side verified billing event দিয়ে status বদলায়। Plan-এর দাম ও limit database-backed; manual-এর কোনো উদাহরণকে চূড়ান্ত commercial offer মনে করবেন না। বর্তমান implementation-এ annual invoice থেকে বারো মাসের credit একসঙ্গে grant হয়; monthly release নয়। এই নীতি production rollout-এর আগে অনুমোদন করা দরকার।

বর্তমান স্থানীয় setup-এ Stripe credentials ও price ID configured নয়। Credit add-ons → Buy credits একবারের credit purchase; verified payment event না আসা পর্যন্ত credits যোগ হয় না। Change an existing plan-এ নতুন plan/interval বেছে confirmation দিলে Stripe prorated invoice তৈরি করে; payment/webhook activation নির্ধারণ করে। Plan change-এর জন্য আরেকটি পূর্ণ credit allowance দেওয়া হয় না; paid billing cycle-এ allowance আসে। Annual cycle-এর allowance ১২ মাসের জন্য একসঙ্গে দেওয়া হয়।

Trial days operator plan অনুযায়ী সেট করেন; একই workspace-এর প্রথম eligible checkout attempt-এ trial পাওয়া যায়। Payment failure-এর grace period operator নির্ধারণ করেন—default ৩ দিন। Grace/period শেষ হলে নতুন research ও monitor check বন্ধ হয়; saved data পড়া যায়। Subscription, invoice ও credits reconcile করে সিদ্ধান্ত নিন।

Development billing sandbox আলাদা করে enabled থাকলে স্পষ্ট sandbox panel দেখা যাবে। Complete sandbox payment অথবা Complete sandbox credit purchase বাস্তব টাকা কাটে না। Sandbox production-এ ব্যবহার করা যায় না। Live Stripe sandbox account-এ পুরো lifecycle acceptance credentials পাওয়ার পরে করতে হবে।

সঠিক origin থেকে API ব্যবহার

অ্যাপের mutation-এ configured app origin ও JSON content type প্রয়োজন। স্থানীয় API docs-এর port 4000, কিন্তু app origin 3000; তাই Swagger page থেকে mutation চালালে Origin-এর কারণে 403 হতে পারে। Origin protection বন্ধ করবেন না।

সাধারণ কাজ UI দিয়েই করুন। API-only admin operation-এর জন্য signed-in অবস্থায় app-এর http://localhost:3000 tab-এ browser developer console খুলে নিচের মতো same-origin request ব্যবহার করা যায়। সব {...} placeholder আগে বাস্তব ID দিয়ে বদলাতে হবে। Account permission server-এ যাচাই হয়। কোনো cookie/token কপি করার প্রয়োজন নেই।

শুধু overview পড়ার উদাহরণ:

const response = await fetch('/api/admin/overview');
const result = await response.json();
console.log(response.status, result);

এই manual কোনো script paste করার মাধ্যমে admin privilege তৈরি করতে বলে না; অনুমোদিত account ছাড়া request প্রত্যাখ্যাত হবে।

৪. Credit adjustment

ব্যবহার করুন: অনুমোদিত support correction বা commercial decision বাস্তবায়নে। Owner-এর সাধারণ research budget-এর জন্য platform credit adjustment প্রয়োজন নেই।

১. GET /api/admin/organizations থেকে সঠিক organization-এর ID, name, credits ও reservedCredits মিলিয়ে নিন। একই রকম নাম হলে ID-ই চূড়ান্ত পরিচয়।

২. Adjustment-এর reason ও কত unit যোগ/বিয়োগ হবে অনুমোদিত support record-এ লিখুন।

৩. App tab-এর console থেকে একবার request পাঠান:

const organizationId = 'REPLACE_WITH_ORGANIZATION_UUID';
const response = await fetch(`/api/admin/organizations/${organizationId}/credits`, {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({
    amount: 50,
    reason: 'Approved correction for support case RS-EXAMPLE'
  })
});
console.log(response.status, await response.json());

৪. সফল হলে organization balance এবং owner-এর Billing & usage → Credit activity-তে ADJUST মিলিয়ে নিন।

amount শূন্য হতে পারে না; বর্তমান গ্রহণযোগ্য সীমা −১০০০০০ থেকে ১০০০০০। Negative adjustment মোট credit-কে reserved credit-এর নিচে নামাতে পারবে না। Reason অন্তত ১০ অক্ষর। প্রতিবার আলাদা request নতুন adjustment হতে পারে—response অস্পষ্ট হলে balance/ledger না দেখে আবার পাঠাবেন না। Ledger entry edit/delete করে correction করবেন না; আলাদা adjustment করুন।

এখন raw failed job recovery, queue cancellation management ও সব dead-letter-এর জন্য পূর্ণ admin UI নেই। Database row হাতে বদলে recovery শুরু করার আগে checkpoint, idempotency ও credit settlement-এর সঙ্গে মিল রেখে developer-reviewed procedure প্রয়োজন।

১০. Customer API key ও webhook সহায়তা

Workspace Integrations-এ API key একবার দেখানো হয়। হারালে পুরোনোটি উদ্ধার করা যায় না; নতুন key দিন ও পুরোনোটি revoke করুন। Account member remove করা আলাদা; organization-owned API key প্রয়োজন হলে আলাদা revoke করতে হবে। Key-এর scope, expiry ও tenant boundary server-এ যাচাই হয়। বর্তমান read-only public endpoints /api/v1/projects ও /api/v1/reports।

Webhook management বর্তমানে API-only, workspace integration permission প্রয়োজন:

Endpoint কাজ
GET /api/organizations/{orgId}/webhooks Endpoint ও সাম্প্রতিক delivery status
POST /api/organizations/{orgId}/webhooks HTTPS receiver URL ও subscribed events দিয়ে endpoint তৈরি; signing secret একবার ফেরত দেয়
DELETE /api/organizations/{orgId}/webhooks/{id} Endpoint disable
POST /api/organizations/{orgId}/webhooks/{id}/retry/{deliveryId} Dead-letter delivery আবার pending করা

বর্তমান events: research.completed ও monitor.changed। Delivery-তে event ID ও timestamped HMAC signature header থাকে। Receiver-কে signature যাচাই ও event ID দিয়ে duplicate handling করতে হবে। ব্যর্থ delivery-তে bounded backoff চলে; ৬ attempt শেষে dead_letter হতে পারে। Delivery/receiver problem না বুঝে বারবার manual retry করবেন না। Private-network receiver বা redirect দিয়ে restriction bypass করা যাবে না। Slack/Discord adapter এখনও নেই।
